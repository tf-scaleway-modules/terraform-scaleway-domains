# Proposal

## Why

This is the module's first adoption of OpenSpec: it never used Agent OS or any other spec-driven workflow, so its contract lives only in the code and the README. The engineering standards are published as pinned OpenSpec stores, and the sibling modules (`vault`, `keycloak`) already plan through them. Adopting OpenSpec now gives every later change a baseline contract to write its delta specs against.

## What Changes

- Configure `openspec/config.yaml`: reference the `quality`, `repository` and `terraform` stores pinned to a tag, and add scaleway-domains-specific `context`, per-artifact `rules` and `operations` guidance.
- Add `AGENTS.md` (project summary, non-negotiables, standards lookup, workflow, precedence, commands) and `CLAUDE.md` importing it.
- Install the `openspec-*` skills for Claude Code (`.claude/skills/`) and OpenCode (`.opencode/skills/`).
- Write the baseline capability specs under `openspec/specs/`, describing the module **as released today**.
- Tooling: pin `node` and the `openspec` CLI in `mise.toml`, add `spec-validate` and `spec-setup` tasks, add `scripts/openspec-setup.sh`, and validate specs in CI through `.gitlab/specs.yml` (job `validate:specs`).
- No change to any `.tf` file, input, output or resource: semver **patch**. `CHANGELOG.md` stays generated by git-cliff.

## Capabilities

### New Capabilities
- `module-contract`: supported tooling and provider, no provider/backend blocks, inputs and their defaults, project resolution, outputs and what they expose.
- `domain-registration`: optional domain registration with an owner contact by ID or inline.
- `dns-zone`: optional DNS zone for a domain or subdomain and the zone outputs.
- `dns-records`: DNS records, their validation, stable keys and the dynamic DNS routing modes.
